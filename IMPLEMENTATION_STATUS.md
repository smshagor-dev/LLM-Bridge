# LLM Bridge implementation status — 2026-11-14

## M0 / M1

Rust/C++ CPU baseline exists. Full-generation byte comparison now strips only an explicitly declared reference prefix; arbitrary suffix matches cannot pass. Benchmark gates retain raw failures and exit nonzero on failed inference or missing required Linux peak RSS. CLI resident generation now uses native cancellation polling. Rust 1.85.1 is pinned, Cargo.lock is committed, and both crates inherit the declared Rust 1.82 minimum. Merged formatting, native lint and an overflowing layout-test fixture were repaired.

## M2 — experimental full-decoder checkpoint

- Existing bounded GGUF index/read/hash/cache and F32/Q8 primitives remain implemented.
- **New:** complete dense Llama F32/Q8_0 streamed prefill/decode: embedding, RMSNorm, RoPE, causal GQA, bounded FP32 KV, SwiGLU, residuals, output head and greedy sampling.
- All model weight rows arrive through bounded Rust reads. Upstream loading is vocabulary-only. `--backend streamed` is explicit; the resident backend remains default.
- **Measured:** pinned stories15M Q8_0 (26,671,328 bytes) completed three eight-token prompt trials under an independently enforced Linux RLIMIT_AS cap of 25,165,824 bytes. Complete generated bytes and 256,000 logits per trial matched the independently built pinned reference with FP32 KV/flash-disabled configuration. Raw JSON evidence records exact peak RSS, source/binary hashes and protocol.
- **New CLI:** `--workspace-mb`, `--address-space-mb` (Linux), `--logits`; cooperative cancellation and context/workspace rejection contracts exercised with the real model.
- Explicit workspace accounting is not a whole-process RSS guarantee. RLIMIT_AS is an address-space ceiling for the standalone CLI/test child, not cgroup memory or a portable per-request limit.
- **Still pending:** adaptive cache/prefetch scheduling, portable authenticated execution sessions, broader architecture/quantization/reference coverage, fault/security hardening, real 2GB hardware and larger-model tests. Do not mark all M2 requirements complete.

## Validation

Local checks: Python regression suite; workspace non-native tests; release native/all-target tests; fmt; native and non-native Clippy; real baseline output/tensor-range/Q8 numerical parity; streamed decoder output/logit parity and enforced address-space trials; real-model cancellation and refusal contracts. Detailed test counts and commands are in `docs/STREAMED_DECODER.md` and PR evidence. CI on the final branch must be confirmed separately.

## Bounded cache integration checkpoint

- Optional `--cache-mb` now connects a fixed-budget session-local block cache/read-ahead to the full streamed decoder. Zero remains the default. Cache hits revalidate source identity and cancellation; failed refills are invalidated.
- Three prompts passed cached/uncached reference output and FP32-KV logits under the same 24 MiB Linux address-space cap with a 1 MiB cache budget. Source range-read calls dropped about 99.6%; source bytes rose about 0.8–0.9%. This is not a physical-disk or speed claim.
- Cache budget includes payload/staging/slot arrays; portable worker limits, authenticated sessions on other platforms, asynchronous prefetch and adaptive scheduling remain pending. See `docs/STREAMED_CACHE.md`.

## Verified model session checkpoint (Linux)

- Optional trusted whole-file SHA-256 now anchors per-block hashes at consumption, not just an earlier standalone verification command. Native tokenizer metadata comes from a sealed/rehashed metadata-only memfd; weight regions remain sparse holes. Native metadata offset is bound to that sealed prefix.
- Added `--sha256` and bounded `--verification-mb`; unsupported platforms/resident backend reject this guarantee rather than downgrade. Default mode remains explicitly unverified.
- Three pinned tiny-model prompt trials passed reference output/logits under 24 MiB RLIMIT_AS. Accounted verification overhead was 807,712 bytes. Same-identity late weight mutation is rejected in a real-model regression. This is content integrity, not a signature/provenance or host-sandbox claim.
- Cryptographic immutable-session integration now has a concrete Linux path; portable sealed metadata/worker isolation, fuzzing, richer model coverage and provider provenance remain pending. See `docs/VERIFIED_MODEL_SESSIONS.md`.

## M3 — native-derived planning checkpoint

- `plan --json` reuses native graph validation to derive workspace/KV coefficients without loading weights or allocating activation/KV arenas. Metadata-only reads are bounded to the GGUF metadata prefix.
- `chat --auto-context` explicitly selects and reports a reduced feasible context; no prompt truncation. Optional incremental admission budgets share cache/verification/runtime/OS reserves. Native execution still rechecks its own workspace requirement.
- Planning budgets are estimates of additional allocations, not total RSS. Linux address-space enforcement remains separate; auto-planning under a cap intersects current remaining virtual headroom. Verified auto-planning authenticates before native metadata inspection.
- Exact native budget boundary and real-model CLI protocols are included. Full hardware/model scheduling, real 2GB-host validation, SIMD/thread adaptation and I/O/compute feasibility remain incomplete. See `docs/STREAMED_MEMORY_PLANNING.md`.

## M3 — measured session performance checkpoint

- Opt-in constant-space session clocks now measure first logits/piece readiness, sampling/emit counts, inter-logits decode rate, range callback and consumer callback wall time. No clock-per-read collection when disabled; no per-token timeline allocation.
- `chat --metrics` exposes successful streamed-session JSON; failures/cancellation do not claim successful timing. EOS/empty-piece and N−1 interval semantics are explicit.
- A real child-process benchmark compares complete instrumented/uninstrumented output hashes, validates counters and optionally gates every trial against requested decode/readiness targets. Reports retain all failures and no raw prompt/response text. CI measures uncached and authenticated cached runs under the existing 24 MiB Linux address-space cap.
- Filesystem page caches are uncontrolled. These measurements are not physical storage bandwidth, isolated CPU compute, a cold-start test or a universal speed guarantee. Full adaptive scheduling remains incomplete. See `docs/STREAMED_PERFORMANCE.md`.

## M3 — adaptive cache admission checkpoint

- Optional `--auto-cache` allocates complete cache slots only after admitting context/workspace and all required reserves. The CLI defaults to a 1 MiB ceiling; explicit zero disables it. Low cache headroom selects zero without reducing context.
- Planner and cache construction share exact allocation geometry; selected byte budgets are used by execution and reported separately from requested ceilings. Manual caches remain mandatory reservations. Required integrity buffers are not sacrificed.
- Pure budget-boundary tests plus real-model zero/minimum/larger cache boundary executions validate context preservation, exact allocations and unchanged output. The CLI protocol includes authenticated adaptive cache and resident-backend refusal.
- This is deterministic admission, not runtime cache resizing or a measured speed optimizer. Full prefetch/thread/compute scheduling remains incomplete.

## Native CPU compatibility checkpoint

- Cargo stamps the explicit x86 AVX2 build profile. Runtime CPU/OS checks guard safe Rust resident/streamed/authenticated generation, native metadata probing and Q8 execution before FFI. CLI generation checks before model inspection. Unknown/disabled/unvalidated profiles refuse native execution.
- `doctor --json` reports native profile, architecture and feature availability without invoking native code. No unvalidated scalar fallback is selected.
- Actual binaries run under QEMU Core 2 Duo CPUID: doctor reports incompatibility, CLI native requests fail normally, and ten direct Rust library paths reject before FFI with no operator range reads. This is negative-path emulation, not physical old-CPU inference or a 2GB-hardware measurement.
- Direct C ABI consumers and custom higher-ISA Rust compiler flags remain outside this Rust admission guard. Generic pre-AVX2/ARM numerical validation and dynamic dispatch remain incomplete. See `docs/NATIVE_CPU_COMPATIBILITY.md`.

## Q4_0 numerical execution and main integration checkpoint

- Dense Llama streamed execution accepts F32/Q8_0/Q4_0 rows using pinned ggml geometry and CPU traits; Q4_1 remains rejected. The pure Q4 fixture is derived reproducibly from the pinned lossy Q8 checkpoint and is not a quality evaluation.
- Align wrapper AVX2/FMA compilation, FP32-square/double-accumulate RMS, normal-RoPE angle iteration, padded FP32 attention and SwiGLU CPU primitives with the pinned numerical configuration. Attention score/value scratch is budgeted explicitly (KV + 8 bytes per context token plus two fixed padding tails).
- Preserve checkpoint hash gates, complete-output/logit comparisons and the original Q8 model-larger-than-24-MiB cap proof. Q4 trials use no cap because their file is smaller than 24 MiB. Reference extra weight buffers/repacking are an explicit, recorded option; tolerance is unchanged.
- Prior #72–#77 merges targeted intermediate branches; main still contained only #71 when inspected. The next integration PR targets main directly and includes these already-reviewed cache/authentication/planning/performance/CPU-admission milestones.
- Other Q4 models, K-quant formats, larger-model/physical-2GB validation and complete adaptive scheduling remain pending. See `docs/STREAMED_Q4_VALIDATION.md`.

## Explicit baseline CPU build checkpoint

- `LLMBRIDGE_CPU_PROFILE=baseline` selects a separate x86-64/SSE2 artifact; `avx2` remains default. Cargo tracks changes, wrapper and ggml profiles match, and unknown values fail the build. Runtime environment changes cannot override the embedded profile.
- Profile-specific CPU/OS admission accepts SSE2 baseline CPUs without AVX. No automatic ISA dispatch or scalar fallback is introduced; other architectures remain unvalidated.
- Matching independent baseline reference protocols exercise authenticated cached Q8/Q4 on the host and under Core 2 Duo emulation. Native Q8 process-cap validation is separate; emulation cannot be labeled as a memory-cap proof. Real old-CPU/2GB hardware and larger-model validation remain pending. See `docs/BASELINE_CPU_BUILD.md`.

## Runtime optional-cache release checkpoint

- A session-local atomic control can release optional cache payload/staging/slots at safe row/logits boundaries without replacement allocation. Current capacities/accounting reach zero; KV/context and authenticated source state remain live. Cache does not regrow during the session.
- Existing generation entry-point signatures/default behavior remain unchanged; the advanced controlled session API explicitly carries optional trusted SHA and cache control. CLI opt-in `--cache-pressure-mb` samples effective available RAM until one release, with conservative handling of unknown samples. It does not bypass initial admission or impose a hard RSS limit.
- Real-model output/logit parity, cancellation and same-identity late mutation are checked after release. Golden trials force the signal with an oversized floor and preserve the original Q8 24 MiB proof. This is not physical RAM-pressure/RSS-reclamation or real 2GB-host validation. See `docs/RUNTIME_CACHE_PRESSURE.md`.

## Hierarchical cgroup-v2 admission checkpoint

- Linux hardware availability now intersects every visible ancestor's own hard-limit/usage headroom, including sibling consumption; total RAM uses the minimum visible hard limit. Resolve actual cgroup2 mount roots/escaped paths and bound traversal/file reads.
- Invalid observable measurements fail closed instead of becoming unlimited. Unlimited leaf usage is valid in additional-allocation admission; process metrics retain leaf semantics. Shared hardware profiling feeds context/cache planning and cache-pressure release.
- Regression fixtures and production filesystem reads cover parent pressure, mount/path/error cases and exact planner/allocation boundaries. Hidden ancestors, v1, atomic snapshots and privileged enforcement/physical low-RAM validation remain outside this checkpoint. See `docs/CGROUP_MEMORY_ADMISSION.md`.

## Fresh authenticated ranges and bounded row batching checkpoint

- Rehash each requested authenticated block on every public range call and bypass the optional LRU; repeated-block/same-identity rewrites must be rejected. Constant-time session detection avoids cloning digest strings per read.
- Group contiguous matrix rows within the existing packed buffer, preserving per-row dot order/cancellation and exact tensor boundaries. No extra weight buffer or asynchronous worker. Range metrics distinguish total/weight callback counts and bytes from source I/O. Authenticated metadata callbacks use bounded reads from the already sealed prefix, preventing repeated whole-block hashing for tiny GGUF fields.
- Real-model chunk geometry, independent reference and cancellation/integrity contracts validate this change separately. Historical authenticated-cache speed/read-count evidence is not current-policy evidence. Configured authenticated cache reservations remain accounted until release/teardown. See `docs/BOUNDED_ROW_BATCHING.md`.

## M3–M11

M3 now has native-derived CLI/context admission, not a complete adaptive scheduler. M4 remote providers, M5 MoE, M6 GPU, M7 API/SDK, M8 desktop, M9 full robustness/benchmarks, M10 format/plugin extensibility and M11 large-model feasibility remain incomplete. No 70B/550B or real 2GB-machine result is claimed.
