# Worker-limited streamed execution

`StreamedExecutor` connects the existing CPU/RAM worker planner to queued native generation. Callers share one executor across their own threads and call `generate()` with existing `QueuedStreamedRequest` values. No worker threads, input queues, output buffers or model copies are created by the executor itself. The existing FIFO handles waiting; native generation still performs model/configuration/authentication checks.

Construction uses the supplied hardware snapshot, requested worker count, OS reserve and maximum session-slot charge. Unknown or insufficient available memory, zero slots/workers/pending capacity and arithmetic overflow are rejected. The selected worker count is capped by logical CPUs, requested workers and the remaining accounted memory budget. OS reserve stays outside the shared session budget.

Every admitted request reserves one **full fixed slot**, including requests whose selected configuration needs less. This prevents small jobs from filling spare byte capacity and exceeding the planned simultaneous-session count. A request whose workspace/source/cache/authentication/runtime charge exceeds the slot is rejected before enqueueing or model I/O. The executor adds only the unused slot allowance to an internal copy of the request; it does not alter context, model, cache configuration, trusted digest or consumers. Returned reservation metrics report the full slot.

Use one instance (for example, shared through `Arc`) for competing sessions. Separately constructed executors have independent budgets and do not collectively bound a process. `worker_count`, `slot_bytes` and `max_capacity_bytes` report the immutable plan. `capacity_bytes` reports the current admission capacity; `reserved_bytes`, `active_sessions` and `pending_sessions` are individual concurrent snapshots. Active means admitted, including authentication and consumer callbacks; it is not an OS thread/CPU-utilization sample. A completed/error/cancelled call releases its slot through the queued wrapper's existing RAII path.

The hardware reading is point-in-time. Default construction does not automatically gate a live executor when system pressure changes. The opt-in [sampled pressure policy](EXECUTOR_MEMORY_PRESSURE.md) gates admission without shrinking capacity. Neither path can enforce process RSS, allocate real memory in advance, set CPU affinity or provide an async/CLI/server worker pool. The per-request metadata/runtime allowance remains an estimate; caller thread stacks, callbacks and other processes can allocate outside this accounting. Coordinate cancellation and conservative reserves; the controls below adjust cooperative admission within the original ceiling. Synchronously nested calls requiring an outer held slot retain the same deadlock restriction as [queued generation](QUEUED_STREAMED_INFERENCE.md).

## Validation

Planner regressions check worker counts and capacity against CPU/request/RAM bounds, unknown measurements and invalid settings. The real pinned Q8 contract requires at least two admitted CPUs and sufficient memory. It starts two native sessions before the direct reference path is warmed up, pauses both at their first-logits callbacks, and requires two full simultaneous slot reservations. Both complete-output hashes and SHA-256 over every FP32 logit must match subsequent direct execution.

A separate one-worker executor holds a native session at its first logits. A much smaller request (which would fit leftover byte capacity under partial charging) must remain pending without opening its nonexistent model path. Cancelling that pending call removes it while preserving the first session's slot; completing the first leaves zero reservations. Oversized requests leave no pending/running charge. The incompatible-CPU protocol now exercises sixteen guarded library paths, including this executor.

Reproduce with `cargo run --release -p llmbridge-core --features native --example streamed_executor_contract -- models/stories15M-q8_0.gguf`. This is tiny-model concurrency/correctness validation, not a throughput, race-detector, physical2GB or large-model feasibility result. Other architectures and workloads require separate measurements.

## Live admission controls

`set_paused(bool)`/`is_paused()` expose the internal FIFO admission gate. A completed pause prevents later admission polls from reserving; already-admitted work may still start or finish. New requests fitting current capacity can wait up to `max_pending`, and cancellation remains available. This does not freeze active execution.

`set_capacity_bytes(bytes)` returns the old capacity, accepts zero and refuses values above immutable `max_capacity_bytes()` without changing state. Restoring the original budget cannot raise the original CPU/RAM worker ceiling. Each request still charges one full slot, so capacity below one slot blocks all new reservations even for small requests; intermediate byte values effectively round admission down to complete slots. `worker_count()` continues to report the original plan, not a live worker count.

Shrinking preserves all active slot charges, which can temporarily exceed capacity. `budget_snapshot()` reports capacity/reserved/available/over-capacity together under one mutex. Pending and paused observations are separate snapshots. No lock is held across native work or a consumer. New enqueues larger than current capacity reject before model I/O; already-pending tickets wait for growth or cancellation. Use pause when bounded new waiting work should still be accepted at the retained capacity. Capacity growth does not resume pause, and resume does not grow capacity. Multiple controllers must coordinate because the latest setter for each control wins; there is no combined atomic policy update. Neither operation samples OS pressure automatically, changes the configured slot size, releases native allocations or bypasses per-session process guards.

The `executor_controls_contract` real-model test queues two calls while paused, then shrinks capacity to zero and pauses again from the first admitted session's logits callback. That session retains a full slot and finishes, while the tail stays pending. Growth/resume admits the tail; above-plan growth refuses, missing-model pending cancellation and zero-capacity refusal leave no charge, and subsequent growth recovers. All three completed executor generations match direct complete-output/every-FP32-logit hashes. Reproduce with `cargo run --release -p llmbridge-core --features native --example executor_controls_contract -- models/stories15M-q8_0.gguf`.

Opt-in automatic pressure gating is documented in [executor memory pressure](EXECUTOR_MEMORY_PRESSURE.md). Manual pause and capacity remain independent of that policy.

Opt-in [admission waiting timeouts](ADMISSION_WAIT_TIMEOUT.md) clean up expired requests while preserving active reservations and policy controls.
