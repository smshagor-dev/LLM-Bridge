# Worker-limited streamed execution

`StreamedExecutor` connects the existing CPU/RAM worker planner to queued native generation. Callers share one executor across their own threads and call `generate()` with existing `QueuedStreamedRequest` values. No worker threads, input queues, output buffers or model copies are created by the executor itself. The existing FIFO handles waiting; native generation still performs model/configuration/authentication checks.

Construction uses the supplied hardware snapshot, requested worker count, OS reserve and maximum session-slot charge. Unknown or insufficient available memory, zero slots/workers/pending capacity and arithmetic overflow are rejected. The selected worker count is capped by logical CPUs, requested workers and the remaining accounted memory budget. OS reserve stays outside the shared session budget.

Every admitted request reserves one **full fixed slot**, including requests whose selected configuration needs less. This prevents small jobs from filling spare byte capacity and exceeding the planned simultaneous-session count. A request whose workspace/source/cache/authentication/runtime charge exceeds the slot is rejected before enqueueing or model I/O. The executor adds only the unused slot allowance to an internal copy of the request; it does not alter context, model, cache configuration, trusted digest or consumers. Returned reservation metrics report the full slot.

Use one instance (for example, shared through `Arc`) for competing sessions. Separately constructed executors have independent budgets and do not collectively bound a process. `worker_count`, `slot_bytes` and `capacity_bytes` report the immutable plan; `reserved_bytes`, `active_sessions` and `pending_sessions` are individual concurrent snapshots. Active means admitted, including authentication and consumer callbacks; it is not an OS thread/CPU-utilization sample. A completed/error/cancelled call releases its slot through the queued wrapper's existing RAII path.

The hardware reading is point-in-time. This does not automatically shrink a live executor when system pressure changes, enforce process RSS, allocate real memory in advance, set CPU affinity or provide an async/CLI/server worker pool. The per-request metadata/runtime allowance remains an estimate; caller thread stacks, callbacks and other processes can allocate outside this accounting. Coordinate cancellation and conservative reserves or recreate the executor when admission policy changes. Synchronously nested calls requiring an outer held slot retain the same deadlock restriction as [queued generation](QUEUED_STREAMED_INFERENCE.md).

## Validation

Planner regressions check worker counts and capacity against CPU/request/RAM bounds, unknown measurements and invalid settings. The real pinned Q8 contract requires at least two admitted CPUs and sufficient memory. It starts two native sessions before the direct reference path is warmed up, pauses both at their first-logits callbacks, and requires two full simultaneous slot reservations. Both complete-output hashes and SHA-256 over every FP32 logit must match subsequent direct execution.

A separate one-worker executor holds a native session at its first logits. A much smaller request (which would fit leftover byte capacity under partial charging) must remain pending without opening its nonexistent model path. Cancelling that pending call removes it while preserving the first session's slot; completing the first leaves zero reservations. Oversized requests leave no pending/running charge. The incompatible-CPU protocol now exercises fourteen guarded library paths, including this executor.

Reproduce with `cargo run --release -p llmbridge-core --features native --example streamed_executor_contract -- models/stories15M-q8_0.gguf`. This is tiny-model concurrency/correctness validation, not a throughput, race-detector, physical2GB or large-model feasibility result. Other architectures and workloads require separate measurements.
