# Experimental full streamed Llama decoder

The CLI now has two explicit CPU paths. `resident` remains the default pinned llama.cpp graph. `streamed` runs every decoder block through bounded GGUF row reads and native ggml CPU dot/activation-quantization kernels. It never invokes the resident weight loader: upstream model loading is **vocabulary only**. No fallback or model substitution occurs.

Implemented: embedding lookup, RMS normalization, Q/K/V projection, normal full-head RoPE, causal grouped-query attention, bounded FP32 KV cache, attention output/residual, SwiGLU feed-forward/residual, output normalization/head, greedy token sampling, prompt prefill and incremental decode. Cancellation is checked at reads and execution/output boundaries. Tokenizer metadata and native parser allocations are separate from the explicitly counted activation/KV workspace.

## Supported scope

Only dense `llama` GGUF models with F32/Q8_0/Q4_0 weights, standard full-head RoPE and the implemented tensor inventory are accepted. Unknown Llama metadata options, extra tensors, unsupported quantization, oversized context and infeasible workspace fail explicitly. `--logits path.f32` creates a new file and refuses to overwrite an existing model, trace or symlink.

Only the pinned **stories15M-q8_0.gguf** has completed the end-to-end golden protocol. Other compatible shapes are experimental, not advertised as verified. Output is raw continuation, not chat-template processing. GPU/MoE/remote inference are not implemented here.

## Run

```sh
cargo build --release --locked --bin llmbridge
llmbridge chat model.gguf --prompt 'The sky is' --backend streamed \
  --ctx 128 --max-tokens 8 --workspace-mb 8 --metrics
```

On Linux, a standalone CLI process can additionally enforce an address-space cap:

```sh
llmbridge chat model.gguf --prompt 'The sky is' --backend streamed \
  --max-tokens 8 --workspace-mb 8 --address-space-mb 24 --metrics
```

`--workspace-mb` budgets native activations, KV, row buffers and projection scratch. It is **not** an RSS cap. `--address-space-mb` lowers this CLI's Linux `RLIMIT_AS` soft/hard limit; it does not raise inherited limits or affect a parent process. This caps mapped virtual address space, which also bounds this process's RSS, but is different from a cgroup-wide physical-memory cap. A too-small cap may cause allocation failure or process termination. It is not a sandbox and does not protect against all native faults. The reusable core does not silently change its embedding application's process limits.

Available-RAM admission now fails closed when measurement is unavailable. Linux is the tested platform; equivalent Windows/macOS resource enforcement is pending. Unknown/incomplete known-cgroup headroom is rejected, but effective ancestor/mount handling still needs hardening.

## Independent validation

Use pinned llama.cpp commit `cd959bae99ff4bed22bef2604f45241c09bbb8c8` (v0.9.0). The instrumentation script only adds a raw-logit dump and an opt-in FP32-KV/disabled-flash configuration to upstream `llama-simple`; its graph/weight execution remains independent.

```sh
git clone --depth 1 --branch v0.9.0 https://github.com/ggml-org/llama.cpp.git reference
python3 scripts/prepare_reference_logits.py reference/examples/simple/simple.cpp
cmake -S reference -B reference-build -DGGML_OPENMP=OFF -DGGML_NATIVE=OFF \
  -DLLAMA_BUILD_EXAMPLES=ON -DLLAMA_BUILD_SERVER=OFF -DLLAMA_BUILD_TESTS=OFF
cmake --build reference-build --target llama-simple --parallel 2
python3 scripts/check_streamed_parity.py --binary target/release/llmbridge \
  --reference reference-build/bin/llama-simple --model models/stories15M-q8_0.gguf \
  --output benchmarks/results/streamed --max-address-space-mb 24
cargo run --release -p llmbridge-core --features native --example streamed_contract \
  -- models/stories15M-q8_0.gguf
```

The constrained protocol applies `RLIMIT_AS` independently in the child before exec, requires the model file to exceed the cap, verifies complete generated bytes after the exact known tokenizer prefix, and compares every vocabulary logit before sampling. FP32 KV is required on **both** paths: comparing the streamed FP32 cache with the reference's default FP16 cache produced different logits even though generated text matched. The protocol keeps tolerance `atol=0.01, rtol=0.001`; measured zero differences in this local run are observations for this checkpoint and host, not a universal bitwise guarantee.

On 13 November 2026 the 26,671,328-byte checkpoint completed all three eight-token prompt trials under a **25,165,824-byte (24 MiB)** address-space cap. Each trial compared 256,000 logits; full generated bytes and logits passed. Peak RSS was below the enforced cap. See the checked-in JSON evidence for exact measurements and binary/source hashes. This is an OS-constrained tiny-model result, **not** a real 2GB-machine experiment, a large-model result, a portable per-request RSS guarantee or a performance promise.

## Remaining work

Production API, desktop, remote storage, MoE and GPU adapters remain pending. M2 is an experimental end-to-end checkpoint rather than a declaration that the whole milestone/product is finished.
