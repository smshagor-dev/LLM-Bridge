# Bounded admission waiting

`generate_streamed_queued_with_timeout(queue, request, cancelled, wait_timeout, on_piece, on_logits)` and `StreamedExecutor::generate_with_timeout(request, cancelled, wait_timeout, on_piece, on_logits)` add an opt-in cooperative waiting budget. Existing generation signatures retain their indefinite-wait behavior and cancellation support. Request/configuration and CPU checks still run before admission; no new FFI or numerical path is added.

The monotonic waiting timer starts after pre-admission validation, before the first pressure sample. It covers initial sampling, enqueueing, queue/budget lock acquisition, waiting polls and subsequent pressure sampling. The timeout is checked before and after sampling, on each waiting iteration and after reservation acquisition before model work. A zero duration refuses before enqueueing or sampling, even when capacity is free. Expiration returns `queued generation admission wait timed out`. Queue wait metrics now include initial pressure sampling as well as enqueue/poll time.

An expired pending ticket is dropped through existing RAII cleanup. This removes that request without changing manual pause, the pressure gate, capacity or another running reservation. If capacity is acquired just as the timer expires, the final pre-model check releases the reservation without opening the model. An expired FIFO head therefore stops blocking later work once sufficient capacity becomes available. Cancellation remains active; a pre-cancelled request reports cancellation before evaluating its zero timeout.

Only waiting is bounded. After admission passes the final check, model authentication/native execution/consumers may outlive the waiting budget and use existing cancellation controls. This is not an end-to-end inference deadline or a hard wall-clock return bound. OS scheduling, lock waits and a synchronous custom sampler can delay observing expiry; an in-flight sampler cannot be interrupted. Remaining-time arithmetic uses elapsed durations, avoiding `Instant + Duration` overflow even for `Duration::MAX`, and cooperative parking never requests more than the remaining budget or the ordinary 5 ms poll interval.

## Validation

Boundary regressions check zero, exact and exceeded deadlines, shorter remaining parks, unbounded old behavior and maximum durations. A deliberately slow polling hook expires before model opening and leaves no ticket/reservation; zero timeout skips the hook, and pre-cancellation retains its error. The real pinned Q8 contract expires a missing-model FIFO head while a real tail waits behind held capacity, then releases capacity so the tail completes. A second waiting call times out while another session holds its full slot at native logits; the active session then runs beyond its own admission budget and finishes normally. Manual pause and unknown pressure also cause clean waiting timeouts; zero timeout does not sample pressure. Subsequent generation recovers with no pending/reserved charge. All three successful generations match direct complete-output and every-FP32-logit hashes.

Run `cargo run --release -p llmbridge-core --features native --example admission_timeout_contract -- models/stories15M-q8_0.gguf`. The incompatible-CPU protocol covers both new Rust entry points among sixteen guarded library paths and requires refusal before FFI/model access. These are tiny-model correctness and cleanup protocols, not throughput, physical low-RAM or large-model feasibility results. CLI/server timeout options and native execution deadlines remain separate work.
