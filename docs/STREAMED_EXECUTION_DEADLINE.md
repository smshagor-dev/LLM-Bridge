# Cooperative streamed execution deadline

`generate_streamed_with_deadline` accepts `StreamedDeadlineControl { control: StreamedControl { expected_sha256, cache }, deadline: Instant }`. This adds an explicit absolute monotonic deadline to one synchronous direct streamed session without changing existing `StreamedControl` literals or untimed entry-point signatures. Use `Instant::checked_add` when constructing a deadline from an untrusted or potentially huge duration. The wrapper does not create timer threads or overwrite the caller's cancellation flag.

An already-expired deadline refuses before model opening or consumer delivery. Once running, expiry is observed during authentication's bounded-read cancellation checks, native polling, model range reads and before/after token/logits consumers. Checks also run between metadata/source setup stages and after the synchronous native call. Caller cancellation remains independent and takes precedence when observed together with expiry. Expiry reports `streamed generation deadline expired`; ordinary cancellation retains its existing errors. Authentication, trusted identity, sealed metadata, process guards and cache ownership remain in place.

A deadline stops further cooperative progress; it cannot preempt in-flight metadata I/O, a filesystem read, an individual native operation or an application consumer. A consumer that crosses the deadline runs until it returns, after which the next check aborts. Tokens already delivered before an expiry remain delivered. No hard wall-clock return limit, maximum poll latency or operating-system thread termination is promised. Session-local model handles and workspace release through the existing Rust/C++ ownership paths when the synchronous call unwinds normally.

This API covers direct-session setup/authentication/native execution, rather than just waiting for admission. Existing `generate_streamed_queued_with_timeout` and executor `generate_with_timeout` still apply only to waiting, and do not acquire an execution deadline implicitly. Queue/executor/CLI/batch deadline propagation remains separate integration work. The numerical implementation and versioned native ABI are unchanged; the new wrapper uses the existing cancellation/poll callbacks.

## Validation

Unit regressions verify pre-expired missing-model refusal and cancellation precedence without changing the flag. Expired poll/read/token/logits callbacks must deliver no data, perform zero source reads, and leave the output buffer untouched. With the deadline removed in the same fixture, those callbacks must work, proving the test does not merely observe contained callback failures.

The pinned Q8 `streamed_deadline_contract` compares a future-deadline authenticated cached session with direct complete-output and every-FP32-logit hashes. Another real session holds its first logits consumer beyond a two-second deadline; callback return must abort with exactly one logits callback and zero token callbacks, leaving the caller flag false. On Linux, open descriptor counts before/after this timed abort must match. Untimed and timed recovery calls then reproduce the direct hashes. Wrong-digest refusal and ordinary caller cancellation are also exercised. This is deterministic boundary testing, not measured physical memory pressure or a deadline-latency benchmark.

Run `cargo run --release -p llmbridge-core --features native --example streamed_deadline_contract -- models/stories15M-q8_0.gguf`. The negative CPU protocol now covers seventeen Rust native execution/probe paths, including the deadline wrapper, before FFI/model access. No throughput, RSS, physical2GB, race-detector or large-model feasibility result is established.
