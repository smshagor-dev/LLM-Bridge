# Sampled memory-pressure admission

`StreamedExecutor::new_with_pressure(hardware, config, policy)` opts into automatic headroom sampling before admission and during waiting-generation polls. Existing `new()` remains manual-only. The default sampler uses `hardware::profile().available_ram_bytes`: on Linux this intersects OS available RAM with every observable cgroup-v2 ancestor; unknown/invalid visible measurements produce `None`. Other platforms currently return unknown. Construction still requires a valid original worker plan.

`MemoryPressurePolicy` sets a low `pause_below_bytes`, a strictly higher `resume_at_bytes`, and a positive shared `sample_interval` of at most 60 seconds. The low floor must cover the configured OS reserve plus one full session slot; checked arithmetic rejects overflow. Initial policy state is closed. A known sample at or above the recovery threshold opens admission. Once open, a sample strictly below the low floor closes it; values in the intervening band preserve the prior state. Unknown samples always close the gate. Recovery therefore needs a fresh high sample, rather than treating an absent limit as unlimited.

The pressure gate is independent of manual `set_paused`: pressure recovery never clears an application pause, and manual resume cannot bypass pressure. `is_paused()` continues to report only manual pause; `pressure_snapshot()` reports the optional policy gate, last observed bytes and sample count together. Budget capacity and its original maximum are unchanged. Capacity zero still rejects new enqueues, whereas pressure pause at retained capacity accepts bounded FIFO waiting work. Every admitted session retains its full fixed-slot charge, including when pressure closes. Cancellation and pending-handle cleanup remain available.

Waiting `generate` calls refresh automatically before each admission poll, with one throttled sampler shared across all competing callers. `refresh_pressure()` also lets an application tick the same sampler; it respects that interval. No monitor thread is created. An idle executor or one with only already-admitted sessions does not sample in the background. The next request refreshes before admission when the sample is due. A cached observation can remain in use for the configured interval; polling/scheduling/I/O add latency, with no hard reaction-time guarantee. This is an admission gate, not an execution freeze, per-request fresh measurement guarantee or OS/RSS limit. Simultaneous new sessions can use the same cached sample; cooperative slot limits and native guards still apply. It does not replan workers or guarantee that current headroom covers all unmaterialized allocations.

Samples, decisions and gate application are serialized in one controller mutex so an older observation cannot overwrite a newer one. Sampling runs without queue/budget locks; gate application takes controller then queue, and admission takes queue then budget. No path takes those locks in reverse, and no model execution or token/logits consumer runs under them. `new_with_pressure_sampler` accepts an application-supplied effective-headroom source for integration and deterministic tests. It must be quick, non-panicking, trustworthy and must not re-enter this executor's pressure methods. Its execution is serialized; cancellation waits for an in-flight sampler to return. A custom source has the same unknown/hysteresis rules and is not inherently a physical measurement.

## Validation and limits

Unit regressions cover exact thresholds, initial hysteresis state, unknown measurements, retained active charges, independent manual gating, shared sampling interval and invalid configuration. The real pinned Q8 `executor_pressure_contract` queues two calls under unknown headroom, recovers automatically on a supplied high signal, then closes pressure from the first session's native logits callback without revoking its slot. The FIFO tail remains pending after the head finishes. A band signal cannot recover; a high signal recovers policy while manual pause remains effective, then manual resume completes the tail. Both complete-output and every-FP32-logit hashes match direct execution.

The same contract exercises the production OS/cgroup sampler with an intentionally unattainable recovery threshold. A missing-model request stays pending without model opening, cancels cleanly, and leaves zero pending/reserved charge. This proves the sampling/admission/cancellation path, not actual physical memory-pressure responsiveness. Run `cargo run --release -p llmbridge-core --features native --example executor_pressure_contract -- models/stories15M-q8_0.gguf`.

No physical low-RAM load, RSS reclamation, throughput, race detector, hidden-cgroup visibility, 2 GB hardware or large-model viability is established. Model authentication, CPU compatibility, numerical paths, process limits and manual budget controls retain their existing semantics. CLI/server integration remains separate.
